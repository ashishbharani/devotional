# Royal devotional homepage

The homepage is generated by `hooks/generate.py` with presentation helpers in
`hooks/royal_home.py`. `docs/stylesheets/royal-home.css` is scoped to `.udhc-home`;
no catalogue, navigation, astronomical engine or reading-link data is rewritten.
The current canonical brand is HDC — Hindu Devotional Collection. The homepage
heading spells out Hindu Devotional Collection. Legacy `.udhc-*` selectors and
anchors remain technical compatibility references; their styling is unchanged.

## Reference and artwork provenance

The owner supplied `Hindu_Devotional_Homepage_Design.zip`, its standalone HTML
and mobile preview on 15 October 2026. Its README describes all bundled images
as custom-generated for that prototype. Only its local WebP artwork is reused;
there are no stock-image hotlinks, external image requests or embedded base64
payloads. This records the supplier's provenance statement, not an independent
copyright investigation. The original supplied archive remains unchanged.

The supplied temple/ghat scene, gold detailing, maroon typography, cream reading
surfaces and discovery-card palette are the primary reference. Ganesha and Shiva
are presented using the supplied framed illustrations. No unsupplied Nandi scene
or archival/site-authenticity claim is invented. Rama, Lakshmi and Hanuman use
textual sacred-name seals rather than incorrectly relabelled deity portraits.

## Preservation and data

The actual catalogue contains **42** canonical categories, not 43. Work, category
and group counts are calculated from the existing data. Discovery cards are
search shortcuts, explicitly distinguished from canonical classifications.
Popular deity URLs are looked up from existing category-1 groups, never guessed.
All existing Today Panchang, library and category disclosures remain available,
including their original live calculation/search/reading functionality.

Hero search is an ordinary GET form to `find/?w=…`, compatible with the existing
universal search and GitHub Pages without extra JavaScript. The global sticky
navigation remains unchanged; a small wrapping homepage navigation maps Help to
the existing legend and About This Collection to the existing foreword.

## QA

`scripts/test_royal_homepage.mjs` checks generated internal links/fragments,
responsive layout, local image loading, keyboard and GET-search behaviour, themes,
reduced motion and instant-navigation return. Existing Panchang browser tests
now test the non-interactive hero-art layer separately from its intentional,
visible search/actions, instead of expecting the retired publication cover.

Before publishing, run the strict MkDocs build, site and translation audits,
homepage tests, and the existing navigation/search/Panchang/Ephemeris tests.
No direct production deployment is performed by this change.

`uv run python -I scripts/test_homepage_hook.py` additionally reproduces the
MkDocs console entry point's temporary import path. Homepage helpers must be
imported when the hook module is loaded, not lazily during page rendering.
This guards the Linux CI failure masked by local `python -m mkdocs` builds.

The complete homepage link audit also found seven pre-existing, date-dependent
Panchang devotional links using a retired category-1 prefix. Only those link
strings are corrected to the existing canonical destination. No festival rule,
observance decision or astronomical calculation changes. The audit now waits
for the live Panchang and checks every rule's link, so the result is date-independent.

## Integration package

The delivery ZIP contains the changed repository files with their original paths,
not an independent replacement website. Apply it only to a clean review branch
based on the tested `47ac38a` main (or review/merge the pushed feature branch).
Do not extract it over uncommitted work. Keep all existing catalogue/data/assets.
Then use the project's locked setup and build:

```sh
pnpm install --frozen-lockfile --ignore-scripts
uv sync
uv run mkdocs build --strict
uv run python scripts/check_site.py
node scripts/test_royal_homepage.mjs
uv run mkdocs serve
```

The existing GitHub Pages workflow publishes only after an approved merge.
No changes to Pages configuration, deployment architecture or canonical URLs
are required. Screenshot and QA-report deliveries are separate from the source ZIP.
